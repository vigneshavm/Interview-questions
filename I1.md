### **JavaScript & TypeScript**  

#### **1. Difference between `var`, `let`, and `const`?**  
- `var`: **Function-scoped**, hoisted, can be re-declared.  
- `let`: **Block-scoped**, not hoisted, prevents redeclaration issues.  
- `const`: **Block-scoped**, immutable reference, must be initialized.  

Example:  
```js
if (true) {
    var x = 10;  // Accessible outside block
    let y = 20;  // Block-scoped
    const z = 30; // Block-scoped & immutable
}
console.log(x); // 10
// console.log(y, z); // Error
```

---

#### **2. What is a Closure?**  
A closure allows a function to **remember its outer scope** even after execution.  

Example:  
```js
function outer(outerVar) {
    return function inner(innerVar) {
        console.log(`Outer: ${outerVar}, Inner: ${innerVar}`);
    };
}
const closureFunc = outer("Hello");
closureFunc("World"); // Output: Outer: Hello, Inner: World
```
**Use case:** **Data encapsulation** (e.g., private variables).

---

#### **3. Synchronous vs. Asynchronous JavaScript?**  
- **Synchronous**: Code executes sequentially, blocking further execution.  
- **Asynchronous**: Operations (e.g., API calls) run in the background without blocking.  

Example (Async/Await):  
```js
async function fetchData() {
    let response = await fetch("https://api.example.com/data");
    let data = await response.json();
    console.log(data);
}
fetchData();
```

### **ReactJS**  

#### **4. What is the Virtual DOM?**  
A **lightweight copy of the real DOM**. React:  
1. Creates a **Virtual DOM** snapshot.  
2. **Diffs it** with the previous state.  
3. **Updates only changed elements** in the real DOM (efficient re-renders).  

Example:  
```js
const [count, setCount] = useState(0);
return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
```

---

#### **5. Controlled vs. Uncontrolled Components?**  
- **Controlled**: State managed by React (`useState`).  
- **Uncontrolled**: DOM manages the state via `useRef`.  

**Controlled Example:**  
```js
const [text, setText] = useState("");
return <input value={text} onChange={(e) => setText(e.target.value)} />;
```
**Uncontrolled Example:**  
```js
const inputRef = useRef();
return <input ref={inputRef} />;
```

## **Interview Q&A: APIs & Connecting Frontend with Backend**  

### **1. What are APIs, and why are they important in web applications?**  
**API (Application Programming Interface)** enables communication between **frontend and backend services**. It allows web apps to fetch, send, and manipulate data from a server.  

✅ **REST API** – Uses HTTP methods (`GET`, `POST`, `PUT`, `DELETE`).  
✅ **GraphQL API** – Fetches only required data (`query`, `mutation`).  
✅ **WebSockets** – Enables real-time communication.  
✅ **gRPC** – Fast, binary-based API for microservices.

---

### **2. Explain the difference between REST and GraphQL.**  

| Feature | REST API | GraphQL |
|---------|---------|---------|
| Data Fetching | Multiple endpoints (`/users`, `/posts`) | Single endpoint (`/graphql`) |
| Data Structure | Fixed response format | Client decides response structure |
| Over-fetching | ✅ Yes (fetches extra data) | ❌ No (fetches only requested fields) |
| Performance | Can be slow due to multiple requests | Optimized, single query fetches required data |

**Example:**  
✅ **REST (GET `/users/1`)**  
```json
{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com",
  "address": "New York"
}
```
✅ **GraphQL (`{ user(id: 1) { name, email } }`)**  
```json
{
  "user": {
    "name": "Alice",
    "email": "alice@example.com"
  }
}
```

Using `fetch()` or `Axios`.

```js
.then(data => console.log("User Created:", data))
.catch(error => console.error("Error:", error));
```

## **Interview Q&A: Building Maintainable & Testable Codebases**  

### **1. How do you ensure that your codebase is maintainable?**  
A **maintainable codebase** follows best practices that make it easy to read, debug, and extend.  

✅ **Key Principles:**  
- **Modularization** – Break code into reusable, independent modules.  
- **Separation of Concerns (SoC)** – Keep logic separate (e.g., UI, business logic, API calls).  
- **SOLID Principles** – Ensure **Single Responsibility, Open-Closed, Liskov, Interface Segregation, Dependency Inversion**.  
- **DRY (Don't Repeat Yourself)** – Avoid redundant code by reusing functions/components.  
- **Consistent Code Style** – Use ESLint, Prettier, and follow team coding conventions.  
- **Type Safety** – Use **TypeScript** to avoid runtime errors.  

✅ **Example: Modular Code (React + TypeScript)**  
```tsx
// Button.tsx (Reusable Component)
import React from "react";

interface ButtonProps {
  text: string;
  onClick: () => void;
}

const Button: React.FC<ButtonProps> = ({ text, onClick }) => {
  return <button onClick={onClick}>{text}</button>;
};

export default Button;
```
Instead of writing separate button components in different places, we create one **reusable button component**.

## **Micro-Frontend Design Pattern – Interview Q&A**  

### **1. What is Micro-Frontend Architecture?**  
**Micro-Frontend (MFE)** is a frontend architecture where a large web application is broken down into smaller, independent **frontend modules**, each developed and deployed separately, yet seamlessly integrated into a single application.  

🔹 **Similar to Microservices but for frontend.**  
🔹 Each team can work on a separate UI module independently.  
🔹 Promotes **scalability, reusability, and maintainability**.  

✅ **Key Benefits:**  
- **Independent Deployment** – No need to redeploy the entire app.  
- **Tech Stack Agnostic** – Different teams can use **React, Angular, Vue, etc.**  
- **Improved Maintainability** – Each module is independently maintained.  
- **Parallel Development** – Faster development with multiple teams.  

---

### **2. How is Micro-Frontend different from a Monolithic Frontend?**  
| Feature | Monolithic Frontend | Micro-Frontend |
|---------|--------------------|---------------|
| Deployment | Entire frontend is deployed together | Each module is deployed independently |
| Scalability | Harder to scale | Easier to scale |
| Tech Stack | Uses a single framework | Can use multiple frameworks |
| Development Speed | Slower (tight coupling) | Faster (parallel teams) |
| Maintainability | Difficult for large applications | Easy to maintain |

---

### **3. What are the different approaches to implementing Micro-Frontend?**  
✅ **1. Web Components**  
   - Uses **Custom Elements**, **Shadow DOM**, and **HTML Templates**.  
   - Framework-independent (works with React, Angular, Vue).  
   - Example:  
   ```html
   <my-widget></my-widget>
   ```

✅ **2. IFrames (Legacy Approach)**  
   - Each MFE runs inside an `<iframe>` but has **performance issues**.  

✅ **3. JavaScript Module Federation (Webpack 5)**  
   - Most **popular** approach using Webpack 5’s **Module Federation Plugin**.  
   - Allows applications to dynamically import code from remote sources.  
   - Example:  
   ```js
   new ModuleFederationPlugin({
       name: "App1",
       filename: "remoteEntry.js",
       exposes: {
           "./Header": "./src/components/Header"
       }
   });
   ```

✅ **4. Single-SPA (Popular Framework for MFE)**  
   - Micro-frontends are **registered and mounted dynamically**.  
   - Supports multiple frameworks (React, Angular, Vue in one app).  
   - Example:  
   ```js
   registerApplication(
       "header",
       () => import("headerApp"),
       (location) => location.pathname.startsWith("/")
   );
   ```

✅ **5. Custom Routing & Proxying**  
   - Uses **reverse proxy (NGINX, BFF)** to serve different MFEs under one domain.  

---

### **4. How does Module Federation work in Webpack 5?**  
Module Federation allows applications to **share code and components dynamically** without rebuilding the entire app.  

✅ **Example:**  
- **App1 (Host Application)**
```js
new ModuleFederationPlugin({
    name: "host",
    remotes: {
        app2: "app2@http://localhost:8081/remoteEntry.js"
    }
});
```
- **App2 (Remote Micro-Frontend)**
```js
new ModuleFederationPlugin({
    name: "app2",
    filename: "remoteEntry.js",
    exposes: {
        "./Button": "./src/components/Button"
    }
});
```
- **Using the Remote Component in App1**
```js
import Button from "app2/Button";
```

---

### **5. How do you ensure communication between Micro-Frontends?**  
Since each MFE runs independently, they must communicate efficiently.  

✅ **Common Communication Methods:**  
1. **Custom Events (Pub-Sub Model)**  
   ```js
   window.dispatchEvent(new CustomEvent("userLoggedIn", { detail: { userId: 123 }}));
   ```
   - Each micro-frontend listens for these events.  

2. **Shared State Management (Redux, RxJS, Zustand)**  
   - Example: Use **Redux Toolkit** to manage shared states.  

3. **Query Parameters / URL-based Routing**  
   - Use `window.history.pushState()` to update state.  

4. **Backend-for-Frontend (BFF) Pattern**  
   - API Gateway centralizes communication.  

---

### **6. What are the challenges of Micro-Frontend architecture?**  
✅ **Challenges & Solutions:**  
| Challenge | Solution |
|-----------|----------|
| Dependency conflicts | Use **Module Federation** to resolve shared dependencies. |

## **Declarative Programming & Unidirectional Data Flow – Interview Q&A**  

### **1. What is Declarative Programming?**  
**Declarative programming** is a paradigm that focuses on **what** the program should accomplish rather than **how** it should do it. It emphasizes **expressing logic** without explicitly defining the control flow.  

✅ **Examples of Declarative Programming:**  
- **React JSX**  
- **SQL Queries**  
- **CSS Stylesheets**  
- **Functional Programming (Map, Filter, Reduce)**  

✅ **Declarative vs. Imperative Programming:**  
| Feature | Declarative | Imperative |
|---------|------------|------------|
| Focus | What to do | How to do it |
| Readability | More readable | Less readable |
| Maintainability | Easier to maintain | Harder to maintain |
| Examples | React, SQL, CSS | Vanilla JS, Loops, DOM Manipulation |

---

### **2. How is Declarative Programming used in React?**  
React follows a **declarative approach**, where we describe the UI based on the application state.  

✅ **Declarative UI in React (JSX Example):**  
```jsx
const isLoggedIn = true;

return (
  <div>
    {isLoggedIn ? <h1>Welcome back!</h1> : <h1>Please log in</h1>}
  </div>
);
```
✅ **Imperative Approach (Vanilla JS):**  
```js
const message = document.createElement("h1");
message.innerText = isLoggedIn ? "Welcome back!" : "Please log in";
document.body.appendChild(message);
```
✅ **Why is Declarative Better?**  
- No direct DOM manipulation.  
- The UI updates automatically when state changes.  
- Easier to debug and maintain.  

---

### **3. What is Unidirectional Data Flow?**  
**Unidirectional data flow** means that **data flows in a single direction** from a parent component to child components.  

✅ **How it Works in React?**  
1. **State is stored in a parent component.**  
2. **Props pass data down to child components.**  
3. **Children cannot modify props directly (read-only).**  
4. **State updates trigger UI re-renders.**  

✅ **Example of Unidirectional Data Flow:**  
```jsx
function ParentComponent() {
  const [count, setCount] = React.useState(0);

  return <ChildComponent count={count} onIncrement={() => setCount(count + 1)} />;
}

function ChildComponent({ count, onIncrement }) {
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={onIncrement}>Increment</button>
    </div>
  );
}
```
🔹 **Parent passes `count` and `onIncrement` as props to the child.**  
🔹 **Child component can trigger updates, but cannot modify `count` directly.**  

✅ **Why Use Unidirectional Data Flow?**  
- Predictable state changes.  
- Easier debugging and testing.  
- Improved maintainability.  
- Avoids unintended side effects.  

---

### **4. How Does Redux Ensure Unidirectional Data Flow?**  
Redux follows a **strict one-way data flow**:  

1️⃣ **Action** → 2️⃣ **Reducer** → 3️⃣ **New State** → 4️⃣ **Component Update**  

✅ **Redux Unidirectional Data Flow Example:**  
```js
// Action
const incrementAction = { type: "INCREMENT" };

// Reducer
function counterReducer(state = { count: 0 }, action) {
  if (action.type === "INCREMENT") {
    return { count: state.count + 1 };
  }
  return state;
}

// Store
const store = createStore(counterReducer);

// Component
function CounterComponent() {
  const count = useSelector(state => state.count);
  const dispatch = useDispatch();

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => dispatch(incrementAction)}>Increment</button>
    </div>
  );
}
```
✅ **Benefits of Redux in Unidirectional Data Flow:**  
- Centralized state management.  
- Ensures **state mutations are predictable**.  
- Helps in debugging via **Redux DevTools**.  

---

### **5. What is the Difference Between Flux and Redux?**  
| Feature | Flux | Redux |
|---------|------|-------|
| Architecture | Multiple stores | Single store |
| Data Flow | Unidirectional | Unidirectional |
| Reducers | No reducers | Uses reducers |
| Debugging | Harder | Easier with Redux DevTools |

---

### **6. How Does Unidirectional Data Flow Work in Vue and Angular?**  
✅ **Vue.js – One-Way Data Flow with Props:**  
```vue
<template>
  <ChildComponent :message="greeting" />
</template>

<script>
export default {
  data() {
    return { greeting: "Hello, Vue!" };
  }
};
</script>
```
✅ **Angular – One-Way Data Binding with `@Input()` and `@Output()`**  
```ts
// Parent Component
@Component({
  selector: 'app-parent',
  template: `<app-child [message]="greeting" (notify)="onNotify()"></app-child>`
})
export class ParentComponent {
  greeting = 'Hello, Angular!';
  onNotify() { alert('Child notified parent!'); }
}

// Child Component
@Component({
  selector: 'app-child',
  template: `<p>{{ message }}</p> <button (click)="notifyParent()">Notify</button>`
})
export class ChildComponent {
  @Input() message: string;
  @Output() notify = new EventEmitter<void>();
  
  notifyParent() { this.notify.emit(); }
}
```

✅ **Why Unidirectional Data Flow in Vue & Angular?**  
- **Improved state management**  
- **Easier debugging**  
- **Better component reusability**  

---

### **7. What are the Key Benefits of Declarative Programming & Unidirectional Data Flow?**  
✅ **Declarative Programming Advantages:**  
1. **Code is more readable & concise.**  
2. **Easier state management.**  
3. **Less prone to side effects & bugs.**  

✅ **Unidirectional Data Flow Advantages:**  
1. **Predictable state changes.**  
2. **Better debugging & maintainability.**  
3. **Encapsulated & reusable components.**  

---

### **8. What are the Common Pitfalls of Declarative Programming?**  
❌ **Overuse of abstraction** – Can lead to performance issues.  
❌ **Higher learning curve** – Developers coming from imperative backgrounds may struggle.  
❌ **Complex state management** – Needs external tools like Redux/Zustand for large applications.  

✅ **How to Overcome These Issues?**  
- Use **memoization** (`useMemo`, `React.memo`) to optimize performance.  
- Follow **best practices** for state management.  
- Keep the component hierarchy **simple and modular**.

## **Common & Reusable Components – Interview Q&A**  

### **1. What are Common and Reusable Components?**  
A **common component** is a UI component that is used frequently across an application (e.g., buttons, modals, input fields).  

A **reusable component** is a component designed with flexibility to be reused in different parts of an application **without modification**.  

✅ **Example:** A button component that accepts different props for styling and behavior instead of hardcoding its appearance.  

---

### **2. What are the Benefits of Reusable Components?**  
✅ **Consistency** – Ensures uniform UI across the app.  
✅ **Maintainability** – Changes are made in one place, reducing bugs.  
✅ **Scalability** – Makes development faster and more efficient.  
✅ **Performance Optimization** – Reduces redundant code.  

---

### **3. How Do You Create a Reusable Button Component in React?**  
A reusable button should accept **props** for customization.  

✅ **Example: Reusable Button Component (React + TypeScript)**  
```tsx
import React from "react";

interface ButtonProps {
  label: string;
  onClick: () => void;
  variant?: "primary" | "secondary";
  disabled?: boolean;
}

const Button: React.FC<ButtonProps> = ({ label, onClick, variant = "primary", disabled = false }) => {
  return (
    <button
      className={`btn ${variant}`}
      onClick={onClick}
      disabled={disabled}
    >
      {label}
    </button>
  );
};

export default Button;
```
✅ **Usage in Different Parts of the App:**  
```tsx
<Button label="Submit" onClick={handleSubmit} variant="primary" />
<Button label="Cancel" onClick={handleCancel} variant="secondary" disabled />
```

---

### **4. How Do You Handle Props for Maximum Reusability?**  
To make a component more reusable:  
✅ Use **default props** (e.g., `variant="primary"`)  
✅ Accept **children** for flexible content  
✅ Allow **event handlers** as props  

✅ **Example: Generic Card Component with Children**  
```tsx
const Card: React.FC<{ title: string; children: React.ReactNode }> = ({ title, children }) => {
  return (
    <div className="card">
      <h2>{title}</h2>
      <div>{children}</div>
    </div>
  );
};

// Usage
<Card title="Profile">
  <p>John Doe</p>
</Card>
```

### **5. How Do You Optimize Performance in Reusable Components?**  
✅ **Use `React.memo()`** – Prevents unnecessary re-renders.  
✅ **Use `useCallback()` for event handlers** – Avoids function recreation.  
✅ **Use `useMemo()` for computed values** – Prevents unnecessary calculations.  

✅ **Example: Memoized Button Component**

```tsx
const MemoizedButton = React.memo(Button);
```
